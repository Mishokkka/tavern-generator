# FBL Tavern Generator

Генератор и менеджер живых таверн для Forbidden Lands в Foundry VTT.

Версия модуля: **0.7.17**  
Проверенная совместимость: **Foundry VTT 13.351**, **Forbidden Lands 13.0.5**.

Модуль создаёт таверны с региональным названием, меню, ценами, запасами, ночлегом, услугами, владельцем, настроением, слухами, завсегдатаями и происшествиями. ГМ может сохранить таверну, назначить её активной, создать связанную сцену и тавернщика. Игроки получают отдельное меню, корзину и оплату с листа персонажа.

## Установка

1. Помести папку `fbl-tavern-generator` в каталог `Data/modules` Foundry VTT.
2. Перезапусти Foundry.
3. Активируй **FBL Tavern Generator** в настройках мира.
4. Открой генератор через консоль:

```js
game.fblTaverns.openGM();
```

Для постоянного доступа можно назначить этот вызов макросу.

## Работа ГМа

Основной порядок работы:

1. Выбери регион, местность, качество и размер.
2. Сгенерируй черновик.
3. При необходимости отредактируй меню, цены, запасы и комнаты. Кнопка «Открыть таверну» откроет её меню и вкладку «Жизнь таверны».
4. Нажми «Подтвердить», чтобы сделать таверну активной для игроков.
5. Нажми «Сохранить», чтобы оставить её в библиотеке сохранённых таверн.
6. При необходимости создай сцену и тавернщика.

«Подтвердить» и «Сохранить» выполняют разные задачи. Активная таверна показывается игрокам. Сохранённая таверна остаётся в закрытом хранилище ГМа и может быть загружена позже.

Вкладка «Жизнь таверны» и кнопка «Новый день» находятся в окне самой таверны, рядом с вкладкой «Меню». Они доступны только ГМу. В генераторе остаются создание и редактирование таверны.

Кнопка «Новый день» после подтверждения обновляет только открытую таверну, даже если активной назначена другая. Несохранённый черновик после этого не добавляется в библиотеку автоматически; изменения возвращаются в открытый генератор этого черновика. Повторное нажатие во время подтверждения или обработки не запускает второй день.

ГМ может открыть активную таверну сразу на вкладке «Жизнь таверны»:

```js
game.fblTaverns.openPlayer({ tab: "life" });
```

Старый вызов `game.fblTaverns.openGM({ tab: "life" })` также открывает эту вкладку в окне таверны.

## Работа игроков

Игрок открывает активную таверну через:

```js
game.fblTaverns.openPlayer();
```

В меню можно:

- искать позиции по названию и описанию;
- выбрать принадлежащего игроку персонажа-плательщика;
- добавить еду, напитки, услуги и ночлег в корзину;
- оплатить корзину с автоматической проверкой цены, остатка и кошелька.

Корзина принадлежит конкретной таверне и очищается при переходе в другую. Во время незавершённой оплаты переход приостанавливается. Изменение цены требует повторного подтверждения суммы; деньги по устаревшей цене не списываются.

Если подтверждение транзакции задерживается, модуль автоматически до двух раз повторяет тот же `requestId` через 12 секунд. Уже обработанная покупка поэтому не создаётся повторно. Только если синхронизация не завершилась после автоматических повторов, корзина предлагает безопасно повторить ту же транзакцию вручную.

## Деньги

Настройка **Currency Mode** поддерживает два режима:

- `auto`: модуль ищет известные поля валюты в листе Forbidden Lands и читает и изменяет именно их;
- `flags`: используется резервный кошелёк во флаге актёра.

Публичный метод `addFlagMoney` сохранён ради совместимости, но теперь добавляет деньги в фактически активный источник кошелька. Если листовая валюта распознана, обновляется лист. Если нет, обновляется резервный флаг.

Номиналы модуля:

- 1 ЗМ = 100 ММ;
- 1 СМ = 10 ММ;
- 1 ММ = базовая единица.

## Хранение и безопасность данных

Полное состояние таверн, включая секреты ГМа, хранится в скрытой JournalEntry:

`FBL Tavern Generator · GM State`

Не удаляй эту запись. Модуль принудительно выставляет право `NONE` по умолчанию и удаляет все явные права отдельных пользователей. Если запись всё же удалить, модуль создаст новое закрытое хранилище после перезагрузки, но удалённые данные автоматически не восстановятся.

При обновлении с 0.7.5 модуль переносит полную активную и сохранённые таверны из старых world-настроек в закрытую JournalEntry. В world-настройке остаётся только публичное представление активной таверны. Список сохранённых таверн больше не синхронизируется игрокам.

Сцены хранят только публичный снимок меню и идентификатор связанной таверны. Такой снимок позволяет открыть меню без активного ГМа, но никогда не считается доверенным источником для покупки. Цена, остатки, брони и «Жизнь таверны» проверяются по закрытому состоянию ГМа.

Сообщения передаются через штатный `module.fbl-tavern-generator` socket Foundry. Модуль рассчитан на доверительный стол: сложная проверка личности отправителя, обмен через User-флаги, Web Crypto и socketlib не используются. Обычное подключение по HTTP в локальной сети поддерживается прежним транспортом.

Покупки обрабатывает один выбранный активный ГМ. На его клиенте покупки, сохранения и смена дня используют общую очередь. Устаревший черновик отклоняется с уведомлением: его нельзя записать поверх уже совершённой покупки. Сохранённая и активная копии одной таверны обновляются вместе. Отмена правки сбрасывается после внешнего изменения и недоступна для совершённой смены дня.

Результат покупки хранится в закрытом журнале и переживает перезагрузку ГМа. При обрыве между списанием и сохранением модуль оставляет запись `pending` и приостанавливает покупки этим персонажем до сверки ГМом. Порядок восстановления описан в [CHANGELOG_0.7.16.md](CHANGELOG_0.7.16.md).

Очередь работает внутри одного клиента. Для записи состояния используй одну вкладку одного ГМа: одновременная работа нескольких GM-вкладок не имеет распределённой блокировки. Смена ответственного ГМа после завершённой покупки поддерживает повтор по сохранённому чеку; одновременные записи разных клиентов такой гарантии не имеют.

## Новый день и Calendaria

При включённой интеграции Calendaria модуль реагирует на смену календарного дня и может обновлять:

- запасы;
- занятость комнат и бронирования;
- часть меню;
- настроение, слухи, завсегдатаев и происшествие.

Без Calendaria автоматического триггера нет. Кнопка «Новый день» в окне таверны обрабатывает только её. Для обработки всех сохранённых таверн и активной таверны используй API:

```js
await game.fblTaverns.advanceTavernDay();
```

Обновлённый запас не превышает штатный `maxStock`. В редакторе поле «Запас после пополнения» задаёт этот максимум, в том числе ноль.

Адаптер поддерживает API и событие `calendaria.dayChange` из Calendaria 1.0.11, включая нестандартную длину суток. При скачке на несколько дней оплаченный срок уменьшается на прошедшее число суток; меню и атмосфера обновляются один раз до итогового дня. Повтор даты и перевод часов назад не уменьшают срок повторно. При смене календаря отсчёт привязывается к новой шкале без списания дней. Ручной «Новый день» всегда означает один дополнительный день.

Редактор не позволяет удалить комнату с действующей бронью, сменить для неё режим ограничения мест или выставить уже оплаченные места свободными. Расширение вместимости допустимо. Сезонные правила теперь сохраняются в новых позициях меню; старые позиции, у которых эти данные были потеряны, нужно сгенерировать заново.

## Сцены

Модуль может создать сцену таверны, выбрать фон по региону и качеству, добавить кнопку меню и разместить связанного тавернщика.

Подробная структура каталогов фонов описана в [SCENE_BACKGROUND_FOLDERS.md](SCENE_BACKGROUND_FOLDERS.md).

Стандартный Scene compendium:

`world.fbl-tavern-scenes`

При архивировании модуль временно разблокирует compendium и возвращает его прежнее состояние блокировки.

## Character Forge

Поддерживается создание тавернщика через `fbl-character-forge` версии 1.4.0 и выше. Выбор отдельного поднабора артов `tavern` требует Character Forge 1.7.0 и выше.

Подробности находятся в [README_INTEGRATION_CHARACTER_FORGE.md](README_INTEGRATION_CHARACTER_FORGE.md).

Стандартный Actor compendium:

`world.fbl-tavernkeepers`

## Quick Access / Expanded Conditions и чистота

При покупке отдельных услуг модуль может изменить состояние чистоты персонажа. Основная интеграция рассчитана на встроенные STAT-состояния `fbl-quick-access`; отдельный старый Expanded Conditions поддерживается только как legacy-совместимость. Порядок интеграции:

1. пользовательский обработчик через `setCleanlinessHandler`;
2. `fbl-quick-access` (`featureWash`, `washStateUuids` и предметы состояний помытости);
3. старый Expanded Conditions;
4. совместимый legacy API;
5. legacy-флаги состояния;
6. резервный флаг модуля.

Замена предмета состояния выполняется транзакционно: новый предмет создаётся до удаления старого, а при ошибке производится откат. При работе с Quick Access таверна помечает собственную замену `fblqaWashTransition`, чтобы встроенный hook эксклюзивности не запускал параллельное удаление тех же состояний.

## Звуки покупок

В настройках модуля доступно отдельное меню звуков для еды, напитков, ночлега и услуг. В смешанной корзине выбирается категория самой дорогой строки. Ошибка воспроизведения звука не отменяет уже завершённую покупку.

## Публичный API

После `ready` API доступен как `game.fblTaverns` и как `game.modules.get("fbl-tavern-generator").api`.

```js
game.fblTaverns.openGM(options)
game.fblTaverns.openPlayer(options)
game.fblTaverns.clear()
game.fblTaverns.getCurrent()
game.fblTaverns.getSaved()
game.fblTaverns.saveCurrent()
game.fblTaverns.addFlagMoney(actor, coins)
game.fblTaverns.setCleanlinessHandler(handler)
game.fblTaverns.validateData()
game.fblTaverns.createScene(tavern, config)
game.fblTaverns.archiveScene(scene, tavern)
game.fblTaverns.randomSceneImage(params)
game.fblTaverns.sceneRegionFolders()
game.fblTaverns.sceneQualityFolders()
game.fblTaverns.sceneCompendiumPack()
game.fblTaverns.characterForgeAvailable()
game.fblTaverns.createTavernkeeper(tavern)
game.fblTaverns.placeTavernkeeperToken(tavern)
game.fblTaverns.regenerateAtmosphere(tavern)
game.fblTaverns.publicTavernView(tavern)
game.fblTaverns.advanceTavernDay()
```

### Права доступа API

Методы, изменяющие состояние мира, предназначены только для ГМа и проверяют права в коде: `clear`, `saveCurrent`, `addFlagMoney`, `createScene`, `archiveScene`, `createTavernkeeper`, `placeTavernkeeperToken` и `advanceTavernDay`. Игрок не должен вызывать их напрямую.

`getCurrent()` возвращает ГМу полное закрытое состояние, а игроку только публичное представление из world-настройки. `getSaved()` доступен только ГМу и для игрока всегда возвращает пустой массив.

Удалённые действия игрока, включая покупки и запросы связи со сценой, должны проходить через штатный интерфейс и native socket `TavernSocket`, а не через прямой вызов изменяющих методов API. Идентификатор отправителя передаёт сам клиент; транспорт рассчитан на доверительный стол и не аутентифицирует отправителя.

`addFlagMoney(actor, coins)` принимает объект вида:

```js
await game.fblTaverns.addFlagMoney(actor, {
  gold: 1,
  silver: 2,
  copper: 5
});
```

## Разработка и проверка

Требуется Node.js с поддержкой ESM.

```bash
npm run verify
```

Команда выполняет:

- синтаксическую проверку JavaScript;
- проверку относительных импортов;
- проверку `module.json`;
- проверку баланса Handlebars-блоков;
- юнит-тесты генерации, миграций, покупок, кошелька, нового дня, публичных данных и ограничений запасов.

Основной контент расположен в `scripts/data`. После изменения таблиц запускай `game.fblTaverns.validateData()` или полный `npm run verify`.
