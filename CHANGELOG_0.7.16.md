# Исправления 0.7.16 — 13 октября 2026

Изменения выполнены в локальной установленной версии модуля и опубликованы в [PR #4](https://github.com/Mishokkka/tavern-generator/pull/4). Основа — 0.7.15, а не более старая версия основной ветки GitHub. Публикация релиза на GitHub не выполнялась. Исходный аудит остаётся в `AUDIT_2026-10-13.md` как описание состояния до правок.

## Что изменено

| Пункт аудита | Результат |
| --- | --- |
| F01 — идентификация отправителя | По пожеланию владельца сохранён обычный native module socket для доверительного стола. После CodeRabbit исправлена только зависимость доставки от разницы часов компьютеров. Криптография, User-document relay и новые зависимости не добавлялись. |
| F02 — предсказуемая атмосфера | Генерация использует отдельное случайное зерно, сохраняемое только в закрытом состоянии. Повторная обработка одной версии стабильна; публичный снимок зерно не содержит. Старые уже созданные слухи автоматически не перегенерируются. |
| F03 — связь с архивной сценой | Для импорта и сохранения связи берётся компендиум из сохранённой таверны или реальной сцены. Данные входящей ссылки больше не подменяют этот источник. Проверяется принадлежность архивной сцены, если в ней есть идентификатор таверны. |
| F04 — перезапись состояния | Общая очередь операций на клиенте ГМа; версия записи обнаруживает устаревший черновик. Активная и сохранённая копии обновляются одним сохранением журнала. Undo не может восстановить запасы поверх покупки. Действия окна ГМа обрабатывают ошибки с уведомлением. |
| F05 — повторная оплата | Чеки сохраняются в закрытом журнале вместе с изменением запасов. Повтор `requestId` после перезагрузки возвращает результат без нового списания, брони, эффекта услуги и сообщения в чат. Неопределённый результат остаётся `pending` и требует сверки. |
| F06 — цена корзины | Корзина обновляет цены и убирает исчезнувшие позиции. Запрос содержит показанную цену каждой строки и итог; ГМ сверяет их до списания. Несовпадение возвращает меню для повторного подтверждения. |
| F07 — календарный срок | Срок брони учитывает число прошедших суток, дату самой брони, повторы событий и движение времени назад. Смена календаря перепривязывает отсчёт без расходования оплаченных дней. |
| F08 — сезонность | Поле `seasonal` переносится из таблиц в создаваемое меню. Показанная сезонная цена проверяется при оплате. |
| F09 — Calendaria | Добавлена поддержка `CALENDARIA.api.getCurrentDateTime()`, `getCurrentSeason()` и структуры `{previous, current, calendar}`. Учтены индексы месяца/дня, начало летосчисления и длина суток. |
| F10 — нулевой запас | Ежедневное пополнение сохраняет `maxStock: 0`. В редактор добавлен максимум пополнения; его можно уменьшить до нуля. |
| F11 — занятые комнаты | Нельзя продать оплаченные места повторно через редактор, удалить забронированную комнату или сменить её режим ограничения. Неконсистентный старый остаток нормализуется с учётом броней. |
| F12 — смена таверны | Корзина привязана к заведению. Переход очищает её, а незавершённая оплата удерживает исходную таверну и запрос. Повторное открытие обычного меню возвращает активную таверну. |
| F13 — названия | Слова местности больше не смешиваются с существительными в шаблонах с прилагательным. Исправлены русские шаблоны с родительным падежом и согласование женского/множественного рода в Лежниземье. Полноценная морфология всех языков не добавлялась. |

Дополнительно:

- Получение одной сохранённой таверны больше не клонирует и не мигрирует всю библиотеку; чтение текущей таверны не копирует историю покупок.
- Сбой обновления публичной копии меню после успешной записи журнала не отменяет состоявшуюся покупку и не возвращает за неё деньги.
- Учтено число истёкших броней у активной, но ещё не сохранённой таверны.
- Правки сохранённого меню отправляются открытым окнам игроков; API `clear()` отправляет уведомление об очистке.
- В окне игрока явно подписан источник денег: лист персонажа либо резервный кошелёк модуля.
- README приведён в соответствие с реально используемым socket и номером версии.

После CodeRabbit:

- Undo при переходе между тавернами больше не сравнивает версии разных заведений. При возвращении показываются актуальные покупки, обновляются параметры формы и признак активной таверны.
- После завершения действия без изменения черновика окно ГМа получает актуальные запасы, даже если уведомление о покупке пришло во время ожидания диалога. Намеренные изменения черновика сохраняются.
- Отключённая помытость Quick Access не мешает включённой интеграции Expanded Conditions. При поиске состояния преимущество получает компендиум выбранного модуля; отключённые функции не обходятся через резервный API или флаги.
- Разница часов игрока и ГМа не блокирует socket-сообщения. Защита от повторной доставки использует время получения на стороне получателя.

Решения по каждому замечанию и ограничения описаны в [разборе CodeRabbit](REVIEW_FOLLOWUP_2026-10-13.md).

## Если оплата прервалась

Обычная задержка ответа решается повтором того же запроса. Если клиент ГМа оборвался между обновлением актёра и записью таверны, автоматическое повторное списание останавливается. Это две разные записи Foundry; общей серверной транзакции у них нет.

ГМ может посмотреть незавершённые покупки в консоли:

```js
const pending = game.fblTaverns.pendingPurchases();
console.table(pending.map(({id, actorId, tavernId, total, createdAt}) =>
  ({id, actorId, tavernId, total, createdAt})));
```

Полная запись содержит исходный кошелёк `walletBefore`, строки чека `result.lines`, сумму и идентификаторы. Сначала нужно сверить кошелёк, остатки и брони:

- Если покупка должна состояться — вручную привести деньги, остатки, бронь и эффект услуги к ожидаемому результату, затем отметить её `completed`.
- Если покупку нужно отменить — сначала вернуть деньги и состояние позиций/броней, затем отметить её `cancelled`.

После сверки **конкретной** записи:

```js
await game.fblTaverns.resolvePendingPurchase(id, "completed");
// Либо, после ручного восстановления состояния:
await game.fblTaverns.resolvePendingPurchase(id, "cancelled");
```

Эта команда только записывает решение ГМа. Она сама не списывает и не возвращает деньги, не создаёт бронь и не применяет эффект услуги. Игрок после решения повторяет оплату той же приостановленной корзины: подтверждённый чек возвращается без повторного списания, отменённый завершается отказом. Не следует вручную удалять служебный журнал или его историю для разблокировки.

## Границы исправления

Основной режим — одна записывающая вкладка одного ГМа. Очередь и проверка версии защищают от пересечения действий внутри этого клиента и от уже полученных устаревших данных. Они не обеспечивают распределённую блокировку между одновременно пишущими GM-вкладками. Выбор ответственного GM-пользователя в socket сохранён; разные вкладки одного пользователя он не различает. Такой протокол намеренно не усложнялся.

Сохранённые покупки остаются в закрытом журнале без автоматического удаления. Это сохраняет защиту от старых повторных запросов, но история постепенно увеличивает размер журнала. Для очень больших библиотек и длительных кампаний разделение хранения по документам остаётся дальнейшим улучшением.

В существующих меню потерянные ранее сезонные данные сами не восстанавливаются: соответствующие позиции нужно перегенерировать. Новые поля состояния совместимы с прежней схемой, ручной перенос таверн не требуется. Ручной «Новый день» означает один дополнительный день; откат календаря не возвращает уже использованный ночлег. При большом скачке времени брони стареют на весь интервал, а запасы, меню и атмосфера генерируются один раз для итогового дня.

Продуктовые предложения из аудита — слухи с развитием, репутация, расширенная экономика, новые игровые события и переработка интерфейса — не включены в этот пакет исправлений.

## Проверка

Итог после CodeRabbit: **71 из 71 теста прошёл**. Статическая проверка **101 скрипта**, ссылок манифеста и блоков Handlebars завершилась успешно. Шесть регрессионных сценариев дополнительно воспроизвели ошибки на копии кода до этих правок. Сообщения об отказах хранилища, публичного обновления и отката в выводе тестов — намеренно смоделированные сбои.

Автоматические тесты выполняют реальный код сервисов и обработчиков с имитацией документов/хуков Foundry. Покрыты конкурирующие сохранения, покупка последней порции, повтор после перезагрузки, отказ частного хранилища, отказ публичного обновления, неполный откат, старые цены, корзина другой таверны, Undo после покупки, бронь после скачка времени, повторные календарные события, произвольная длина дня, комнатные ограничения, сезонность и выбор архивной сцены.

Дополнительно проверяются все 2016 комбинаций параметров генерации, синтаксис скриптов, ссылки манифеста и структура блоков Handlebars.

В этой сессии не было подключённого игрового клиента Foundry. Реальный совместный сеанс ГМ + игрок и визуальная проверка окон в Foundry после правок не выполнялись. Для приёмки достаточно проверить в своём мире оплату корзины, изменение цены перед оплатой, бронь и переход Calendaria на несколько дней.

Команды проверки:

```sh
npm run check
node --test --test-isolation=none tests/core.test.mjs
```

Флаг `--test-isolation=none` использован только при запуске в ограниченном окружении проверки. Штатная команда `npm test` в модуле не изменена.
